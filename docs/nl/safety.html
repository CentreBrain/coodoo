De agents werken zelfstandig. Binnen harde grenzen.

De failsafes van Coodoo houden riskante acties tegen voordat ze gebeuren. Ze staan altijd aan: geen doel, agent of knop kan ze uitzetten.

Wat nooit mag

Deze regels beschermen je code, je accounts en je sleutels, ook als een agent een fout maakt of een doel verkeerd begrijpt.

  • Je repository wordt nooit verwijderd, gearchiveerd, overgedragen of openbaar gemaakt
  • Geen force pushes, geen herschreven geschiedenis, geen verwijderde branches of tags
  • Sleutels staan versleuteld in een kluis, nooit in een commit, en staan als REDACTED in elk logboek
  • De agents schrijven alleen in je projectmap en kunnen niet bij je GitHub-login
  • Alleen vooraf toegestane acties op GitHub, en commits op jouw naam
  • Werk komt alleen via de stappen van je flow op je hoofdbranch
Failsafe: push geweigerd

git push --force zou de geschiedenis op GitHub herschrijven. Het doel stopt; er is niets veranderd.

Sleutel buiten de commit gehouden

Een bestand met een sleutel uit je kluis is niet gecommit. In het log staat REDACTED.

Zo werkt het

  1. 1Een agent of opdracht probeert iets wat een regel verbiedt.
  2. 2Coodoo houdt het tegen voordat er iets verandert.
  3. 3Het doel stopt of slaat die stap over, en je krijgt een melding.
  4. 4Alles wat een failsafe tegenhield, staat in een logboek dat je in Instellingen kunt lezen.

Grenzen, geen garantie

De failsafes maken werken met AI een stuk veiliger, maar ze kunnen niet elk risico uitsluiten: AI kan fouten maken, en de app die het team bouwt, draait met jouw eigen rechten. Lees de disclaimer en de risico’s van AI.

Veelgestelde vragen

Kan ik de failsafes uitzetten?

Nee. Ze staan altijd aan, ook voor jou. Zo kan een fout ze nooit ongedaan maken.

Kan de AI mijn wachtwoorden en sleutels zien?

Sleutels gaan in de versleutelde kluis van Coodoo en worden in logboeken onleesbaar gemaakt. De agents krijgen geen GitHub-login; je app krijgt een sleutel alleen als jij hem doorgeeft.

Waar zie ik wat er is tegengehouden?

In Instellingen → Failsafes, met wat er geprobeerd werd, wanneer en waarom het werd tegengehouden.
