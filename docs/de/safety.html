Die Agenten arbeiten selbstständig. Innerhalb fester Grenzen.

Die Failsafes von Coodoo stoppen riskante Aktionen, bevor sie passieren. Sie sind immer aktiv: Kein Ziel, kein Agent und kein Knopf kann sie abschalten.

Was nie erlaubt ist

Diese Regeln schützen deinen Code, deine Konten und deine Schlüssel, auch wenn ein Agent einen Fehler macht oder ein Ziel falsch versteht.

  • Dein Repository wird nie gelöscht, archiviert, übertragen oder öffentlich gemacht
  • Keine Force-Pushes, kein umgeschriebener Verlauf, keine gelöschten Branches oder Tags
  • Schlüssel liegen verschlüsselt in einem Tresor, nie in einem Commit, und erscheinen in jedem Log als REDACTED
  • Die Agenten schreiben nur in deinen Projektordner und kommen nicht an deinen GitHub-Login
  • Auf GitHub nur vorab freigegebene Aktionen, und Commits auf deinen Namen
  • Arbeit erreicht deinen main-Branch nur über die Schritte deines Flows

So funktioniert es

  1. 1Ein Agent oder Befehl versucht etwas, das eine Regel verbietet.
  2. 2Coodoo stoppt es, bevor sich etwas ändert.
  3. 3Das Ziel stoppt oder überspringt diesen Schritt, und du bekommst eine Benachrichtigung.
  4. 4Alles, was ein Failsafe gestoppt hat, steht in einem Log, das du in den Einstellungen lesen kannst.

Grenzen, keine Garantie

Die Failsafes machen die Arbeit mit KI deutlich sicherer, können aber nicht jedes Risiko ausschließen: KI kann Fehler machen, und die App, die das Team baut, läuft mit deinen eigenen Rechten. Lies den Haftungsausschluss und die Risiken von KI.

Häufige Fragen

Kann ich die Failsafes abschalten?

Nein. Sie sind immer aktiv, auch für dich. So kann ein Fehler sie nie aushebeln.

Kann die KI meine Passwörter und Schlüssel sehen?

Schlüssel kommen in den verschlüsselten Tresor von Coodoo und werden in Logs geschwärzt. Die Agenten bekommen keinen GitHub-Login; deine App bekommt einen Schlüssel nur, wenn du ihn ihr gibst.

Wo sehe ich, was gestoppt wurde?

Unter Einstellungen → Failsafes, mit dem, was versucht wurde, wann und warum es gestoppt wurde.
